# AGENTS.md

## Project overview

Trajon is a Go desktop market-data and candlestick-chart application. It uses `github.com/egoist/mygo` for the native UI and `github.com/oneo-me/onevra/source` for shared UI components and icons.

The module currently targets Go 1.27.3. Keep dependency versions pinned in `go.mod` unless an upgrade is explicitly requested.

## Repository layout

- `main.go` — process entry point; delegates to `internal/app`.
- `internal/app/` — application state, MyGo views, market-page orchestration, instrument selection, candles, and chart UI state.
- `internal/market/` — market-domain types, source interfaces, registry/loader behavior, indicators, and source-independent logic.
- `internal/market/adapters/` — exchange-specific candle-source implementations (currently Binance and OKX).
- `internal/market/defaults/` — default source registry and instrument catalog.
- `internal/chart/` — chart viewport calculations and other rendering-independent chart behavior.
- `internal/journal/` — manual trading records, drafts, screenshot validation, and atomic local persistence; independent of market/replay execution.
- `internal/locales/` — Simplified Chinese and English JSON/ICU catalogs, generated typed MyGo message accessors, and language preferences.
- `internal/ui/` — small reusable UI helpers.

Keep exchange/API concerns in adapters, domain behavior in `internal/market`, and presentation/state orchestration in `internal/app` or `internal/ui`.

## Development commands

Run from the repository root:

```sh
gofmt -w .
go run github.com/egoist/mygo/cmd/mygo i18n check .
go run github.com/egoist/mygo/cmd/mygo generate .
go test ./...
CGO_ENABLED=0 go test ./...
go run github.com/egoist/mygo/cmd/mygo vet .
```

Use targeted package tests while iterating, for example `go test ./internal/market/...` or `go test ./internal/app`. Run the full suite before finishing code changes.

## Testing guidelines

- Write tests only for core logic: domain calculations, data integrity, request/cache semantics, and critical state transitions. Cover meaningful boundaries and concrete regressions with a small, focused set of cases.
- Do not add tests for trivial getters/setters, pass-through wrappers, static copy, styling, layout, or framework behavior. Verify purely visual UI changes manually.
- Avoid duplicate coverage, exhaustive combinations without a demonstrated risk, implementation-detail assertions, and elaborate mocks or test infrastructure. Do not add tests merely to increase coverage or require a new test for every change.

## Releases

- `mygo.json` defines the application identity, version, and signed-update public key. Keep `identifier` and the public key stable after release; never commit the private key.
- `.github/workflows/release.yml` currently releases macOS only (`darwin/arm64` and `darwin/amd64`). Push a `v<version>` tag matching `mygo.json` to check catalogs and generated accessors, run tests and MyGo UI vet, build with the pinned MyGo CLI, and upload installers and signed updates to a Draft Release. Set the repository secret `MYGO_UPDATER_PRIVATE_KEY` to the signing key's contents. Review and publish the draft manually; reruns can replace draft assets but must not overwrite published releases.
- Updater signatures do not replace macOS Developer ID signing or notarization; those are not yet configured in CI.
- The settings toolbar's right-hand Changelog button switches from Info to Download when a signed-feed update is available. Startup and opening Changelog without a known update check asynchronously; failures offer retry without claiming the app is up to date. The dialog is 312px wide without an update, 780px with an update, and its notes area is capped at 390px tall, all constrained by the window's modal insets. The dialog has no visible title: a centered header shows the bundled app logo, the Trajon name with a smaller running version beside it, and an icon-only GitHub hyperlink beneath (never the raw URL). It also shows the new version and scrollable Markdown changelog when available. Its bottom-right “Install Update” action downloads/verifies/installs through MyGo, shows progress, permits retry on failure, and relaunches only on success. Dismissal restores opener focus without canceling an install; window closure cancels update jobs and rejects late results. Release builds use a curated CHANGELOG.md when present, otherwise CI creates its version section from the draft release body before building; edit notes before building so the update manifest contains them.

## Go and domain conventions

- Follow standard Go formatting and error handling. Prefer small, deterministic functions and explicit dependencies.
- Preserve the identity semantics of `market.Instrument.Identity()` and the request/cache semantics of `market.CandleRequest.CacheKey()` when changing market models.
- Implement new data providers through `market.CandleSource` and register them through the market registry; do not put provider-specific branching in UI code.
- Keep candle timestamps, ordering, intervals, pagination boundaries, and provider-symbol conversions covered by tests.
- Avoid mutating shared candle slices unexpectedly. Use the existing clone helpers where ownership crosses a boundary.
- The base instrument catalog bundles BTC/USDT spot and perpetual contracts on Binance and OKX; the registry adds provider-owned, offline starter suggestions through `market.InstrumentSuggestionsSource`. Non-empty crypto searches discover currently tradable spot and linear perpetual instruments through `market.InstrumentSource`, with independent five-minute market-catalog caches. Query-based providers instead implement `market.InstrumentQuerySource` and own their code/alias matching; neither the shared searcher nor the picker should re-filter those already-matched results by the raw query. The picker has All / Spot / Futures / Stocks tabs; Longbridge resolves exact US/HK/SH/SZ security codes through static-info and supplies a small stock/ETF starter list for name matching, not a fictional whole-market text search. HK provider codes are unpadded (`700.HK`), while displayed codes use five digits (`00700.HK`). Source-provided Chinese/English names and quote currency are metadata, never identity/cache-key components. Search work is debounced and canceled/rejected on query changes, picker dismissal, and window closure; partial failures keep successful results selectable, and an optional disconnected stock source must not turn every crypto search into an error. Recent successful explicit selections (including stocks) are deduplicated by full instrument identity, capped at 12, and atomically persisted to `trajon/instrument-history.json` under `os.UserConfigDir()`; clickable history appears below the search field.
- Longbridge candles use the official read-only HTTP quote transport (`/quote/history-candlesticks` and `/quote/static-info`) with the existing vault-backed OAuth owner, Bearer / client-ID / DC-region headers, cancellable rate limiting, serialized refresh rotation, and no SDK plaintext token cache or live trading calls. Support HK, US, and Shanghai/Shenzhen securities with forward adjustment and regular trading sessions only. All eleven toolbar periods map to native Longbridge periods; do not synthesize missing/non-trading bars. Normalize candles to sorted, deduplicated UTC timestamps, enforce exclusive history `Before`, and translate offset dates/minutes into Hong Kong / Shanghai / New York exchange time (including US DST), not the machine timezone. Recalculate indicators after history prepends as for crypto. The fixed stock policy remains forward-adjusted, but do not display an Adjusted/前复权 badge or extra label in the chart toolbar. Replay continues to use the common fractional-quantity, long/short simulation engine: it does not model board lots, T+1, dividends, corporate-action position changes, or currency conversion. Journal and replay capital/P&L always use USD without currency selection or conversion; provider quote currency remains metadata only. Changing instruments still resets the session.
- Keep network and other slow work off the UI thread. Reject stale market-load results when the selected instrument/timeframe changes, and close loaders when the window closes.

## MyGo UI rules

- Store application data, widget state, and `ui.Handle` values—not transient `ui.Element` or parts that expire after a build pass.
- Give stateful controls stable, unique keys before construction and preserve identity across rebuilds. Never derive keys from translated labels; the navigation helper avoids Onevra SidebarItem's label-based key.
- Sidebar navigation contains Overview, Trading journal and Replay; instrument history remains in the instrument picker.
- Overview is a journal-performance dashboard, not replay or live-account performance. One valid, fully closed journal is one outcome, including all its additions/reductions; calculate exact decimal P&L as `-sum(signed quantity * price)` in USD, without unrecorded fees, contract multipliers, conversion or unrealized positions. An explicit review save is not required. Filter by recorded Close time (exclusive end) and aggregate days in local time. All records use USD, including legacy records with absent or previously different `currency` metadata; ignore that obsolete field on load and omit it on save, with no exchange-rate conversion. There is no currency selector or currency filter. Invalid execution history is repairable from Overview, never counted as zero P&L. Show total P&L, whole-trade win rate (including breakeven in the denominator), average win/loss ratio and monetary maximum drawdown from a zero-origin cumulative curve; equal Close timestamps are aggregated before drawdown. No closed trades/all-breakeven ratios show a dash, wins without losses an infinite ratio. Trend lines are unsmoothed steps, not fictitious account equity. The daily P&L heatmap uses monthly calendar cells for month ranges and horizontally scrollable annual cells for year/all-time ranges, with year navigation for all-time. Profit/loss shades share a symmetric amount scale and distinguish no trades from breakeven. Hover/focus explains the day; selecting it lists its trades without changing journal selection, and opening a record preserves drafts through the existing history route. Include instrument/tag breakdowns and recent closes. Native statistics run off-thread on immutable snapshots, reject superseded filter/revision and closed-window results, and never use painting callbacks for work or controls.
- Trading journal is a separate page, never embedded in Overview. It has a resizable 260px-first list (220px minimum) and an embedded record/review editor (340px minimum); below 600px of content width, list and detail become back/forward routes. Search covers instrument, prose, tags and unsubmitted text; All / In progress / Closed filters follow committed phases. Hide entirely blank records, but keep incomplete execution inputs; reuse a genuinely blank record for New without overwriting drafts. Rows are grouped by local creation date and ordered newest-created-first, never by edit/save time. Show instrument, stage, a one-line review/latest-note excerpt, up to two tags and creation time; reviewed status requires a successful explicit review save and no later edits. Selecting history preserves entry edits and new-entry drafts and opens completed trades in Review unless an entry edit is pending; it must bypass quick-entry's automatic next-blank behavior. Embedded Save keeps the editor open. A popout transfers the editor to the existing native panel, leaving a dock action in the journal page; only one window builds the shared editor at a time, including redraws of a hidden panel. Selecting a history row or docking returns ownership to the journal page without losing drafts. Load journals asynchronously at main-window startup, and publish persistence results to both views even when the panel is hidden.
- The top-right Quick record icon on Overview and Trading journal opens a reusable, resizable, frameless native `Panel` at launcher level with popover vibrancy, not an in-window modal. It stays above other apps and remains visible on blur; reopening retains its resized dimensions. The narrow-first journal places its borderless headline instrument input, read-only inferred net-position badge, and close button in one draggable top row. History and new-record management live in the Trading journal page, not the floating panel. Records / Review and the entry-type selector use intrinsic-width capsule segmented controls, never full-width tracks or stretched segments; center labels horizontally and vertically within their capsules. Records contains a plain chronological timeline with date groups and a creation-time gutter. The entry-type capsule follows committed trading phases: only Plan initially; Note / Open after submitting a non-empty Plan; Note / Add / Reduce / Close while holding; and no new-entry kinds after a complete Close. Hide the composer and entry-type capsule entirely after closing; completed records permit only viewing, editing existing entries, and review. Enforce the no-new-notes rule in the domain as well as the UI, and handle an empty action list without indexing it. Typing an unsubmitted plan does not unlock trading. Historical entries edit in place using their original kind. Plan and Note are text entries. Every new or edited Open / Add / Reduce / Close requires both a nonzero signed fractional quantity and a positive finite price. Buys are positive, sells negative, and recorded quantities sum exactly to infer long / short / flat; a negative reduction of a long is not itself a short. Add must have the position's sign; Reduce must oppose it and be strictly smaller than the remaining position. Selecting Close prefills the exact opposite of the remaining net quantity, read-only, including positive buy-to-cover quantities for shorts. Close must clear the full position. Editing an earlier action or deleting it must not introduce newly invalid downstream trades; failures preserve both entries and drafts. Legacy incomplete notes remain readable rather than being erased. Do not provide a manual direction selector. Execution prices are required; reasons remain optional. Entry timestamps are assigned at creation and are not editable; editing preserves the original timestamp. Existing entries edit in place and expose editing/deletion through a native ellipsis/context menu rather than two persistent icons on every row; preserve an unsubmitted new-entry draft while editing, and never bind the composer Handle to both editors in one build pass. Legacy separate plans migrate into Plan entries, and schema v1 unsigned execution sizes/drafts migrate to signed buy/sell quantities using their prior direction and operation kind. Schema v2 persists these conversions only with the next atomic save; do not convert them again. These are manual notes, never live or simulated orders. Enter inserts a newline; Cmd/Ctrl+Enter submits only from the entry editor. Review contains one Markdown-source trade-summary editor without a preview toggle, at 75% of the previous editor height, inline tags with independent remove buttons, and responsive screenshot tiles with a labeled add tile. Do not show trade activity in Review. Review is disabled until a committed Close makes the net position exactly zero; the same gate applies to pointer, keyboard, programmatic activation, image attachment work, and explicit review saves. Removing a Close relocks Review without deleting its saved summary or attachments. Entering Review focuses the summary editor. There is no separate next-step field. Only Review accepts image selection, paste, and drop; recording never exposes image attachment actions. Screenshots have local validated copies (PNG/JPEG/GIF/WebP/BMP, at most 20 MB / 24 megapixels each, 20 per record), previews and removal. No remote Markdown images are fetched. Records, active selection, incomplete inputs, and entry edits are asynchronously restored and atomically persisted to `trajon/journal/records.json` under `os.UserConfigDir()`, with content-addressed PNGs under `images/`. Draft saves are debounced and never dismiss the panel; explicit Save flushes without clearing the record and automatically hides the panel only after a successful write, restoring opener focus. Failed explicit saves keep the panel open and allow retry; a successful retry also hides it. Editing, starting new attachment work, switching tabs/records, dismissal, or reopening cancels any older save's pending auto-close so late results cannot hide a later edit or opening. Reopening the hidden panel after a completed review was explicitly saved successfully starts a new blank record while preserving the saved one, including after restart; unfinished drafts, post-save edits, and failed saves reopen the existing record. Wait for pending loads/writes before deciding to start a new record, and do not create another record just because an already-visible panel is activated again. Failures retain drafts and offer retry, and a failed load must not overwrite the existing journal. Image/file work stays off-thread and rejects results after record/tab changes, dismissal, or window closure. Escape and native close hide the panel and restore opener focus without activating the main window; image previews and in-place entry editing consume Escape before it hides the panel. Main-window closure destroys the panel and drains queued journal writes after the event loop exits.

- Settings contains a Data sources / Longbridge section with browser OAuth only (no pasted API keys). The public-client flow uses PKCE and a loopback-only `http://localhost:41927/oauth/callback`, separate from Pulse's port; a single AES-256-GCM encryption key is stored through app-scoped `mygo.Secrets`, never shared with Pulse. OAuth grants can exceed `mygo.MaxSecretSize` (2560 bytes): keep client registration and grant payloads as authenticated ciphertext in `longbridge/*.enc` under `mygo.App.Path(mygo.PathUserData)` (separate Trajon / Trajon Dev directories; unpackaged `go run` uses a `longbridge-standalone` subdirectory to avoid case-insensitive path collisions), never as plaintext configuration or token-cache JSON. Cache the encryption key in its store and the loaded grant in its `Client`; after a successful new-format startup, only one protected key read is needed, and repeated settings restores/quote requests must not reread vault entries. Legacy single-item/chunked records are migration-only: commit a synced, atomic encrypted replacement before best-effort retirement of the old reference. An existing new-format file must never fall back to stale legacy data on decryption/read failure, and a durable absence marker must prevent failed legacy cleanup from resurrecting a disconnected grant. Never silently regenerate a missing key while ciphertext relies on it. Failed saves/deletions preserve the previous active and saved grant. Keep startup auto-restore enabled; one-time migration can still require access to legacy items, and an ad-hoc rebuild or locked keychain can still require macOS confirmation. Do not weaken keychain ACLs or use an identity-only ad-hoc designated requirement to suppress that confirmation. Startup and opening settings restore authorization and refresh near-expiry tokens off-thread; persist rotated refresh tokens immediately and retain a failed rotation in memory for a secure-store retry. Accept optional OAuth refresh tokens and omitted lifetimes (the SDK's one-hour fallback), numeric or quoted-integer `expires_in`, and long lifetimes within Go duration bounds. Access-only grants remain authorized until expiry, then require browser reauthorization; never attempt an empty-token refresh. OAuth error details may identify the endpoint or invalid field, but must never include response payloads or credential values. Browser waiting can be canceled; Cancel, settings dismissal, and window closure reject stale grants and late browser opens. Only an accepted grant starts an atomic secure save, which may finish after settings dismissal; failed reauthorization or removal must not destroy the previous grant. Disconnect removes this app's saved tokens while keeping its client registration; it does not revoke the grant on Longbridge's website. Show authorization separately from network errors, and do not equate an authorized grant with real-time quote entitlements. Stock-picker connection entry opens the same settings flow and restores its query, tab, and search focus on dismissal. A failed candle request requiring authorization can retry after a successful grant only if its pending request still matches and replay is not locked. Connection changes invalidate only Longbridge's reusable candle cache, not already displayed candles/replay or crypto caches. HTTP results from a replaced/disconnected grant are rejected and read-only adapter requests may retry once against the new grant. Longbridge authorization must not gate Binance/OKX use or imply live trading.
- Use `Window.Update`/the established update path to publish background results; do not mutate UI state directly from worker goroutines.
- Keep drawing callbacks limited to painting and use existing MyGo/onevra components for controls, focus, keyboard behavior, and accessibility.
- Use the project’s existing tester patterns only for UI lifecycle or focus changes that affect core correctness or prevent a concrete regression; avoid broad UI test coverage. Consult the pinned MyGo source before relying on an API.

## Change hygiene

- Keep user-facing copy concise and consistent across the Chinese/English catalogs; preserve existing Chinese UI terminology and do not add decorative or marketing copy.
- Do not commit generated build artifacts, credentials, or local build output. The generated `internal/locales/catalog_gen.go` is required source: keep it with its catalogs so plain `go build` and `go test` work without the CLI.
- Prefer a focused change over broad refactors. If behavior or public project conventions change, update this file; update focused tests when core logic changes, following the testing guidelines above.
